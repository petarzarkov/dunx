dunx live demo

This is examples/full from the dunx repository, running unmodified on a Raspberry Pi 5 behind a Cloudflare tunnel. Every panel below calls the same routes the example's tests and OpenAPI document are generated from.

What this process is doing

RequestMetrics, QueryMetrics and EventLoopLag read out of the running container at /api/demo/vitals, refreshed every five seconds. The request and socket counts are read off Bun.serve rather than counted.

busiest route calls p50 p99

Dependency injection

No @Injectable(), no @Inject(), no reflect-metadata. @dunx/transform reads the constructor's parameter types at load time and the container resolves them. The source below is read off disk with Bun.file at /api/demo/source/:name, so it is the file this process was built from. 


          

        


        

          
Transactions

          

            /api/ledger/transfer moves an amount between two rows
            inside one drizzle transaction. Failing it mid-way answers 409, and
            the unchanged row count in the message is the rollback.
          

          

            
            
            
          

          

        


        

          
Retry and backoff

          

            @dunx/http/client calling an upstream that answers 503
            twice before it works. Every attempt the retry policy made comes
            back with the millisecond it happened at, so the jittered backoff is
            visible rather than described.
          

          

            
          

          

        


        

          
Guards and roles

          

            One controller, three answers. @Public opts a route
            out, a class-level @Roles covers the rest, and a
            method-level one overrides it. Nothing here reads a session helper -
            the guard reads route metadata.
          

          

            
            
            
          

          

        


        

          
Websocket gateway

          

            @Gateway('/chat') on the same Bun.serve as
            every route above, broadcasting over Bun's native pub/sub. Open a
            second tab to see the other side.
          

          

            
            
            
            
          

          

        


        

          
Rate limit

          

            @Throttle({ limit: 3, windowSeconds: 60 }) on
            /api/limits/burst. The counter is in Redis when Redis
            is up, and in memory when it is not.
          

          

            
          

          

        


        

          
Image pipeline

          

            Bun.Image at /api/images/render. The
            source is generated at runtime from a 4x4 seed, so there is no image
            file in the repository.
          

          

            
            
            
            
          

          

          

        


        

          
Queue

          

            POST /api/jobs/thumbnails enqueues through bullmq over
            Bun.RedisClient, and the handler runs in a forked
            process. Watch it in bull-board under Queues.
          

          

            
          

          

        


        

          
Session

          

            better-auth mounted by @dunx/auth, with the anonymous
            plugin so there is no form to fill in. The audit route wants a role
            this guest does not have.
          

          

            
            
          

          

        


        

          
Two API explorers, one document

          

            @dunx/openapi generates the document; a renderer serves
            a page over it. Swagger UI is at
            /api/docs and Scalar at
            /api/reference, both reading the same
            openapi.json. Each ships behind its
            own subpath and its own optional peer, so an app installs the one it
            mounts. Both self-host: the check below reports what each page
            weighs and whether anything on it resolves off this origin.
          

          

            
          

          

        


        

          
Validation

          

            One zod schema per route, used to validate the request and to
            generate the OpenAPI document. A rejected body answers 400 with the
            issues zod raised.
          

          

            
            
          

          

        


        

          
Trace context

          

            A W3C traceparent sent to /api/trace is
            adopted, so every log line that request writes carries the same
            trace id and the response carries traceresponse.
